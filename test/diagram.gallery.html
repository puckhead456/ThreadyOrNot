3D diagram visual gallery (dev only — reads copyrighted PDFs from ../tmp-pdf at runtime; nothing here is committed)

For each curated fixture: fetch the PDF, PdfText.extract, Store.splitSections, then one card per section with the finished piece (all rounds worked, interactive:true, auto-rotate on) next to the PDF's own photo. Nothing is written to the app's real localStorage: parts live in memory, the store is pointed at ZD4_gallery_store, and the reviewer's shape classes / verdicts live under ZD4_gallery. Geometry numbers come from DiagramGeo.classify/fit — the same pure module the renderer lays out with, asserted by test/diagram.test.html — so a card and its canvas can no longer drift apart. Drag a canvas to rotate it; double-click resets.
Blank canvases? WebGL draws from requestAnimationFrame, which a browser stops in a window that is minimised, occluded or not compositing (an embedded preview pane, a hidden second monitor). Bring the window forward and the cards paint. PDF pages are rasterised with pdf.js print intent for the same reason — a display-intent render task in such a window never settles.
